### O Planejamento do Componente

Para que o `BusinessStatusIndicator` seja realmente funcional e não apenas um componente visual estático, ele precisa de algumas inteligências por trás:

1. **Fuso Horário:** Como o hotel fica em Campo Grande - MS, o componente deve usar o timezone `America/Campo_Grande` (fuso de Mato Grosso do Sul) usando o `dayjs`, garantindo que o hóspede veja o status correto mesmo se o celular dele estiver no fuso de São Paulo ou de outro país.
2. **Atualização em Tempo Real:** O componente terá um `useEffect` que roda a cada 1 minuto (60 segundos) para recalcular o status (ex: virar de "Aberto" para "Fecha em breve" automaticamente sem precisar recarregar a página).
3. **Lógica de Vários Turnos:** O código precisará lidar com arrays de horários (ex: restaurantes que abrem pro almoço, fecham, e reabrem pro jantar).

````markdown
# Contexto e Objetivo

Você atuará como Engenheiro de Frontend Sênior e especialista em UX/UI de luxo. Seu objetivo é criar do zero o componente `BusinessStatusIndicator.tsx` para o projeto do Brivanna Hotel (Campo Grande - MS).
Este componente será responsável por exibir visualmente se um estabelecimento indicado está Aberto, Fechado, Abre em breve ou Fecha em breve, cruzando o horário atual com o JSON de horários.

## 1. Tipagens Necessárias (Props)

O componente deve aceitar as seguintes props baseadas na interface já existente:

```typescript
type TimeSlot = { open: string; close: string };
type DaySchedule = TimeSlot | TimeSlot[];
export type Schedule = { is24h?: boolean } & {
  [key: string]: DaySchedule | boolean | undefined;
};

interface BusinessStatusIndicatorProps {
  schedule: Schedule;
  businessHours: string;
}
```
````

## 2. Regras de Negócio e Fuso Horário (Client-Side)

- **Timezone Fixo:** Você deve usar a biblioteca `dayjs` configurada com os plugins `utc` e `timezone`. A hora base para todos os cálculos DEVE ser forçada para `"America/Campo_Grande"`.
- **Polling (Tempo Real):** Utilize um `useEffect` com `setInterval` para recalcular o status atual a cada 60 segundos.
- **Lógica de Status (Retorne um Enum/Type: `OPEN`, `CLOSED`, `CLOSING_SOON`, `OPENS_SOON`, `24H`):**
- `24H`: Se `schedule.is24h === true`.
- Determine o dia da semana atual em Campo Grande (0 = Dom, 6 = Sáb) e pegue a agenda de hoje (`schedule[currentDay]`). Cuidado com estabelecimentos que não abrem hoje.
- Trate arrays de turnos (ex: almoço e jantar).
- `OPENS_SOON`: Se está fechado, mas falta `<= 60 minutos` para o próximo `open` de hoje.
- `CLOSING_SOON`: Se está aberto, mas falta `<= 60 minutos` para o `close` do turno atual.
- `OPEN`: Se a hora atual está estritamente dentro do `open` e `close`.
- `CLOSED`: Qualquer outro cenário fora do horário de funcionamento.

## 3. Design System (Premium Hotel Standard)

O design deve ser minimalista, contido, sem badges coloridas gigantes. Use um indicador em formato de ponto (dot) ao lado do texto. O layout deve ser `flex items-center gap-2 mb-5 mt-1`.

**Mapeamento de Cores e Textos (Tailwind):**

- **24H / OPEN:**
- Dot: `w-1.5 h-1.5 rounded-full shrink-0 bg-emerald-500/80`
- Texto: "Aberto agora" ou "Aberto 24h" - `text-xs font-light tracking-wide text-emerald-400/90`

- **CLOSING_SOON:**
- Dot: `w-1.5 h-1.5 rounded-full shrink-0 bg-amber-500/80`
- Texto: "Fecha em breve" - `text-xs font-light tracking-wide text-amber-400/90`

- **OPENS_SOON:**
- Dot: `w-1.5 h-1.5 rounded-full shrink-0 bg-[#ca993d]/80`
- Texto: "Abre em breve" - `text-xs font-light tracking-wide text-[#ca993d]`

- **CLOSED:**
- Dot: `w-1.5 h-1.5 rounded-full shrink-0 bg-rose-500/50`
- Texto: "Fechado" - `text-xs font-light tracking-wide text-rose-300/50`

**Ao lado do Status:**
Adicione um bullet point semântico `<span className="text-white/20 text-xs select-none">•</span>` seguido da prop `businessHours` formatada com `<span className="text-xs text-muted-foreground font-light tracking-wide">{businessHours}</span>`.

## 4. Regras Estritas de Código (NÃO NEGOCIÁVEIS)

1. **Zero Comentários:** O código final DEVE estar limpo, não adicione `//` ou `{/* */}`.
2. **Zero Inline Styles:** Proibido o uso de `style={{...}}`.
3. **Clean Code e Modularidade:** Crie funções auxiliares fora do componente principal se a lógica de cálculo de tempo com `dayjs` ficar muito extensa.
